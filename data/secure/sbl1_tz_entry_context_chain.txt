# SBL1 -> TrustZone entry: what is established and where the chain stops (sbl1.elf and tz.img; Ghidra 12.1.3 decompiles and capstone scans)

1. TrustZone entry (tz.img, 0x14680000; data/ghidra/tz_entry.txt): the first instructions set tpidr_el0 = x0 and tpidr_el1 = x1, then clear sctlr_el3 bit 0 and jump through a pointer. So the first argument is the boot thread's block, and its content is supplied by the caller.

2. Loader objects in SBL1:
   - FUN_1482EEF4 (boot_mbn_loader.c, 0x221 in its assert) fills an 11-entry method table. [0] = FUN_1482EB30, [1] = FUN_1482ED44, [10] = FUN_1482EE9C (transfer). It is referenced from FUN_1482B0FC (call at 0x1482B150).
   - FUN_1482EE9C: calls the verify method of the object at +0x20, then FUN_1482F4AC, then method +0x18 of the object at +0x28 with the loader object as argument. That object at +0x28 is not identified.
   - FUN_1482DB74 (the caller that holds the partition driver result) calls FUN_148612EC, then uses an object with vtable offsets 0xD8 and 0xE8 and, at the end, method +0x18 of its loader object.
3. Region registration (FUN_148612EC; data/ghidra/sbl1_xblconfig_partition_evidence.txt): 0x14680000 (size 0x2B000) is registered as type 5 (TrustZone image). It is the same address as the TZ entry.
4. EL3 to non-secure hand-off (FUN_1482CB70): sets ELR_EL3 from its argument, SPSR_EL3 = 0x1C5, SCR_EL3.NS = 1, then ERET to EL1. This hand-off goes to the non-secure world, not to TrustZone.
5. Writes of a function pointer at offset 0x18 in sbl1.elf: one hit, a stack slot (stp x10, x11, [sp, #0x18] at 0x148272A4). No heap or static block receives the invoke pair in SBL1 code.

Where the chain stops: the object at loader +0x28 (step 2) is the piece that would call into the TZ entry with its context. It is not identified, and no code in sbl1.elf writes the TZ invoke pair at +0x18/+0x20 of a block. The context for the TZ boot thread is therefore built by code either in the object at +0x28 or in an image outside sbl1.elf. Observed; not confirmed.
